# LiftHaul — Backend Hosting Runbook (PostgreSQL)

**Goal:** turn the public GitHub Pages links from the *offline demo layer* into the
*real LiftHaul application* by hosting the backend with PostgreSQL and pointing the
frontend at it.

**Status when this runbook was written (2026-08-23):**
- ✅ Backend code is production- and Postgres-ready. Schema self-applies on first boot
  (`Dockerfile` runs `python migrate.py` → `db.connect` → `dbconn.apply_schema`).
- ✅ Full provider-onboarding acceptance flow passes **33/33** in production posture,
  and the live HTTP routes (register → OTP → login → workspace → add vehicle →
  accreditation fee → eligibility) were exercised over the wire. See
  `docs/go_live/ONBOARDING_ACCEPTANCE_EVIDENCE.md`.
- ✅ One-click Blueprint (`render.yaml`), production `Dockerfile`, and
  `docker-compose.yml` (Postgres 16 + web) are in the repo.
- ✅ Frontend production switch is wired: `config.js` (`window.RGO_CONFIG.apiBase`).

**Why the AI cannot finish this step for you:** hosting requires actions that must be
performed under your own credentials and are, by policy, yours alone — creating the
hosting account, attaching a payment method, and (optionally) changing DNS. Everything
*around* those actions is already done. Each step below is a ~1–2 minute click.

---

## Option A — Render Blueprint (recommended: web + managed Postgres in one shot)

1. **Create/sign in** to a Render account → https://dashboard.render.com  *(you)*
2. **New + → Blueprint** → connect the GitHub repo `marcuslaysontrenova/lifthaul-os-demo`
   → Render reads `render.yaml` and shows: `lifthaul-db` (Postgres) + `lifthaul-api` (web). *(you)*
3. It will prompt for the **one** un-synced env var: **`CORS_ORIGINS`** → set it to your
   Pages origin, e.g. `https://marcuslaysontrenova.github.io`  *(you)*
   - `DATABASE_URL` is injected from the database automatically.
   - `APP_SECRET` is generated by Render automatically (you never see or type it).
4. **Apply** → Render builds the Docker image, provisions Postgres, runs `migrate.py`
   (creates the schema), then starts the API. Wait for **Health = live** (`/health`). *(automatic)*
5. Copy the service URL, e.g. `https://lifthaul-api.onrender.com`.

> Plans: `render.yaml` uses `free` to prove the links are real. Free web spins down when
> idle (cold starts) and free Postgres is time-limited — bump both to paid (`starter` /
> `basic-256mb`) for an actual client pilot. One line each in `render.yaml`.

## Option B — Railway (you already use it for TrenovaTech)

1. Railway → **New Project → Deploy from GitHub repo** → `lifthaul-os-demo` (uses the `Dockerfile`). *(you)*
2. **Add → Database → PostgreSQL**; Railway sets `DATABASE_URL`. *(you)*
3. Add variables: `APP_ENV=production`, `CORS_ORIGINS=https://marcuslaysontrenova.github.io`,
   and `APP_SECRET=<a long random string>` (Railway → Variables → generate). *(you)*
4. Deploy; confirm `/health` returns `{"status":"ok"}`.

## Option C — Local production-parity (no cloud, for your own verification)

Requires Docker Desktop:
```
cp .env.example .env      # set POSTGRES_PASSWORD, APP_SECRET, CORS_ORIGINS
docker compose up --build # postgres:16 + backend, schema auto-applied
```
Then run the acceptance flow against real Postgres:
```
DATABASE_URL=postgresql://lifthaul:<pw>@localhost:5432/lifthaul \
  python scripts/go_live/provider_activation_e2e.py     # expect: 33 passed, 0 failed
```

## Flip the public links to live (after the API is up)

1. Edit **`config.js`** → set `apiBase` to your hosted origin (https, no trailing slash):
   ```js
   window.RGO_CONFIG = { apiBase: "https://lifthaul-api.onrender.com" };
   ```
2. Commit + push. GitHub Pages redeploys. Now the landing page → **Register Free** →
   `provider.html`, plus `portal.html` and `console.html`, all talk to the live API.

## Verify it's really live (not demo)

```
curl -s https://<your-api-origin>/health            # {"status":"ok","env":"production"}
```
Then on the site: register a provider → you should receive a **real OTP** (production
posture never returns the code in the API response) → verify → sign in → your carrier
workspace shows **server-persisted** data. If registration says *"honest offline demo —
no backend configured,"* then `config.js` `apiBase` is still empty.
